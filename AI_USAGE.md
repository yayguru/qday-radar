# AI usage

QDay Radar was built with an AI coding agent (Grok Bot, running in a Linux sandbox with Foundry, Node and the Cloudflare API), directed and reviewed by the human author.

## Workflow

1. **Research**: the agent read the fest rules, the prize page and the `create-qorechain-dapp`, `@qorechain/sdk`, `@qorechain/evm` and `@qorechain/qorex-rainbowkit` packages, and found that the PQC precompiles `0x0A01`/`0x0A02` are active on testnet (it called `pqcKeyStatus` live with `cast` before designing around it) and that QoreX does not yet sign EVM transactions.
2. **Design**: it proposed using the chain's own precompile as a fail-closed gate for attesters and successors, and a two-key "hybrid succession" proof (legacy ECDSA signature + caller with a registered ML-DSA key).
3. **Code**: contract, Foundry tests, scanner, worker, UI, operator CLI.
4. **Verification**: `forge test` (12), `vitest` (10), `tsc --noEmit`, a local `wrangler dev` run and live calls against the deployed worker, including a fix after Cloudflare egress was rate-limited by one public RPC (fallback RPC lists).

## Generated vs human

| Part | Generated by the agent | Human |
|---|---|---|
| `src/QDayRadar.sol`, tests | yes | reviewed scope and threat model |
| `app/*` scanner, worker, UI | yes | product decisions (chains, risk levels, wording) |
| `scripts/ops.ts` | yes | ran the testnet deploy with own faucet funds |
| `scripts/window.ts` | from the official template | — |
| Project idea, submission, video voice-over review | assisted | final call |

No AI model runs inside the product; the scanner is deterministic.
